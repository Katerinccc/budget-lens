# 0007 — gRPC between the BFF and the Api

- **Status:** Accepted
- **Date:** 2026-10-12

## Context
The NestJS BFF (TypeScript) and the .NET Api are separate runtimes owned by the same
codebase. Their contract changes often during development, and a silent mismatch
(renamed field, changed type) would only surface at runtime. The browser never calls the
Api directly, so the internal protocol does not need to be browser-friendly.

## Decision
- The BFF calls the Api over **gRPC** with Protobuf messages.
- **Contract first:** `.proto` files in `protos/` are the single source of truth. C# server
  stubs are generated by `Grpc.Tools`; TypeScript types by ts-proto. Generated code is never
  edited by hand.
- Packages are versioned (`budgetlens.v1`). Fields are never renumbered or reused; removed
  fields are marked `reserved`.
- **Money is never `double`.** Protobuf has no decimal type, so a shared
  `DecimalValue { int64 units; sfixed32 nanos; }` message carries amounts, with a currency
  code. Conversions are centralized in one unit-tested mapper per side.
- Every call has a deadline. Failures use gRPC status codes, which the BFF maps to HTTP
  responses for the browser.

## Alternatives considered
- **REST + OpenAPI-generated clients:** a valid contract-first option and easier to debug
  with ordinary HTTP tools. Not chosen because `.proto` gives a stricter, smaller contract,
  first-class code generation in both languages, and streaming if needed later.
- **GraphQL in the BFF:** unnecessary for a single client with known screens.

## Consequences
- Breaking contract changes fail at compile time on both sides.
- Smaller binary payloads and HTTP/2 multiplexing; at this scale the performance gain is a
  secondary benefit, not the driver. Any performance claim must be backed by a benchmark.
- Debugging needs gRPC-aware tools (Postman gRPC, grpcurl); server reflection is enabled
  in Development only.
- Hosting must support HTTP/2 end to end (Kestrel locally, Azure Container Apps ingress with
  HTTP/2 transport in the cloud).
